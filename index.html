How I make engineering decisions

The questions interviewers ask most, answered the way I work.

Flow or Apex?

I start declarative. Record-triggered Flow handles simple field updates and notifications. I move to Apex when logic spans many records with complex branching, needs callouts with retries, or must be unit-tested as a domain rule. I keep one automation entry point per object event so the order of execution never surprises anyone.

Which integration pattern fits?

Request and reply: REST callout through a Named Credential. Fan-out or fire-and-forget: Platform Events. Replicating record changes: Change Data Capture. External systems pushing in: Pub/Sub API or a custom REST resource with an idempotency key. Live read-only data: Salesforce Connect. Legacy partners: SOAP or Outbound Messages.

How do I stay inside governor limits?

Bulkify everything: no SOQL or DML in loops, Unit of Work for batched DML, selective queries on indexed fields and Platform Cache for hot reads. I move heavy work to Queueable chains or Batch Apex and assert on the Limits class in tests so a regression fails the build instead of production.

How do I test?

Test data factories, @TestSetup, HttpCalloutMock for every callout and tests that run 200 records through each trigger. I cover negative paths and permissions as well as the happy path, and I measure behavior rather than chasing the coverage percentage. LWCs get Jest tests for rendering and events.

How do I handle failure in integrations?

Assume the other side is down. Every message carries an idempotency key and correlation ID, retries use exponential backoff from custom metadata, and after the final attempt the payload lands in a dead-letter object that support can replay. Nothing is silently dropped.

Integration

Enterprise Integration Hub

LTM, Aug 2022 - Feb 2026

The problem
Orders, accounts and cases had to stay in sync with external ERP and ticketing systems without hitting limits or losing messages when those systems went down.
My approach
An event-driven pipeline. A trigger publishes a Platform Event, a Queueable with a Finalizer calls the API through a Named Credential using OAuth, retries back off exponentially, and exhausted messages move to a replayable dead-letter object.
The result
No lost messages, safe retries through idempotency keys, and a support-friendly view of every failed sync.

Agentforce Auto Case Response

Agentforce · Salesforce Knowledge · Flow · LWC

The opportunity
Give service agents a faster first response by bringing a case summary, relevant approved Knowledge, and a suggested reply into the case workflow.
How it could work
An Agentforce service agent follows a defined case-support topic, uses authorized case context and grounded Knowledge, then prepares a draft and next-step suggestions in an agent-facing panel.
Human control
The assigned agent reviews the source articles, edits the response, and chooses whether to send it. Low-confidence or unsupported requests are handed back for manual handling.
